= NetApp Ransomware Resilienceのユーザーアクティビティ検出要件
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
NetApp Ransomware Resilienceのユーザーアクティビティ検出機能により、ユーザーレベルのランサムウェアイベントに対応できます。ユーザーアクティビティ検出を有効にするには、テナントとエージェントのセットを作成する必要があります。検出機能を有効にする前に、Ransomware Resilienceがイベントを適切に検出して報告できるよう、記載されているオペレーティングシステム、サーバー、およびネットワークの要件を満たしていることを確認する必要があります。



[[user-activity-tenant]]
== ユーザーアクティビティテナント

ユーザーアクティビティの検出を有効にするために、ユーザーアクティビティイベントをRansomware Resilienceと共有できるようにするテナントが設定されます。Ransomware Resilienceがテナントをデプロイする地域とクラウド プロバイダを選択できます。


NOTE: テナントの地域展開は、Consoleエージェントに影響しません。Consoleエージェントの展開は、これらの地域とは無関係です。

テナントは、AWSおよびAzureの以下のリージョンにデプロイできます：

|===
| クラウド プロバイダ | リージョン 


| AWS  a| 
* アジア太平洋（シドニー）（ap-southeast-2）
* ヨーロッパ (フランクフルト) (eu-central-1)
* 米国東部（バージニア北部）（us-east-1）




| Azure | 米国東部 
|===


[[user-activity-agent-requirements]]
== ユーザーアクティビティエージェントの要件

テナント作成後、ユーザーアクティビティ検出を有効にするには、ユーザーアクティビティエージェントを作成する必要があります。ユーザーアクティビティエージェントはConsoleエージェントではありません。ユーザーアクティビティエージェントは、別のコンピューティングインスタンスとしてデプロイする必要があります。

ユーザーアクティビティエージェントが以下の要件を満たし、推奨事項を遵守していることを確認してください。



[[operating-system-requirements]]
=== オペレーティング システム要件

疑わしいユーザー行動の検出は、次のオペレーティングシステムでサポートされています：

[cols="2"]
|===
| オペレーティング システム | サポート対象のバージョン 


| アルマリナックス | 9.4 (64 ビット) から 9.5 (64 ビット)、および 10 (64 ビット) (SELinux を含む) 


| CentOS | CentOS Stream 9 (64 ビット) 


| Debian | 11 (64 ビット)、12 (64 ビット)、SELinux を含む 


| OpenSUSE リープ | 15.3 (64 ビット) から 15.6 (64 ビット) 


| Oracle Linux | 8.10 (64 ビット)、および 9.1 (64 ビット) から 9.6 (64 ビット) (SELinux を含む) 


| Red Hat Enterprise Linux | 8.10 (64 ビット)、9.1 (64 ビット) から 9.6 (64 ビット)、および 10 (64 ビット) (SELinux を含む) 


| ロッキー | 9.4（64 bit）から9.6（64 bit）まで、SELinuxを含む 


| SUSE Linux Enterprise Server | 15 SP4 (64 ビット) から 15 SP6 (64 ビット)、SELinux を含む 


| Ubuntu | 20.04 LTS （64 bit）、22.04 LTS （64 bit）、および24.04 LTS （64 bit） 
|===

NOTE: ユーザー アクティビティ エージェントに使用するマシンは、他のアプリケーションレベルのソフトウェアを実行しないでください。専用サーバーをお勧めします。

 `unzip` コマンドはインストールに必要です。 `sudo su -` コマンドは、インストール、スクリプトの実行、およびアンインストールに必要です。



[[server-requirements]]
=== サーバー要件

サーバーは次の最小要件を満たしている必要があります。

* **CPU**: 4コア
* **RAM**: 16GB RAM
* **ディスク容量**：36 GBの空き容量




==== サーバーの推奨事項

* ファイルシステムを作成するために、追加のディスク容量を確保してください。ファイルシステムに少なくとも35GBの空き容量があることを確認してください。+  `/opt`がNASストレージからマウントされたフォルダである場合、ローカルユーザーはこのフォルダへのアクセス権を持っている必要があります。ローカルユーザーに必要な権限がない場合、ユーザーアクティビティエージェントの作成が失敗する可能性があります。
* ユーザーアクティビティエージェントは、Ransomware Resilience環境とは別のシステムにインストールしてください。エージェントとRansomware Resilienceを同じマシンにインストールする場合は、50～55GBのディスク容量を確保してください。Linuxの場合、 `/opt/netapp`に25～30GB、 `/var/log/netapp`に25GBのスペースを割り当ててください。
* Network Time Protocol (NTP) または Simple Network Time Protocol (SNTP) を使用して、 ONTAPシステムとユーザー アクティビティ エージェント マシンの両方の時刻を同期することをお勧めします。




==== サイジングの推奨事項

ユーザーイベントを収集する際は、ユーザーアクティビティエージェントをホストするマシンが、イベント発生頻度に対応できる十分なサイジングになっていることを確認してください。つまり、ユーザーアクティビティエージェントをホストするマシンに、1秒あたりのイベント数を処理するのに十分なデータコレクタ、CPU、およびRAMが確保されていることを確認します。データコレクタの数を増やすには、RAMまたはCPUの容量を増やす必要がある場合があります。Ransomware Resilienceは、ユーザーアクティビティエージェントごとに最大50個のデータコレクタをサポートします。

次の表は、サイジングに関する一般的なガイダンスを示しています。

|===
| ユーザーアクティビティエージェントマシン構成 | データコレクタの数 | 最大イベントレート 


| 4コア、16GB | 10個のデータコレクタ | 20,000件のイベント/秒 


| 4コア、32GB | 20個のデータコレクタ | 20,000件のイベント/秒 
|===
ご自身の具体的な要件を計算することもできます。適切な規模を計算する際には、30%のバッファー率で適格性を判断することをお勧めします。この式を使用して、お使いの構成が負荷に対応できるかどうかを判断してください。

[listing]
----
Where E is the sum of all events per second across all data collectors:

E + (0.3 x E) < 20,000 events/second
----
.Ransomware Resilienceでイベントデータレートを計算する
[%collapsible]
====
Ransomware Resilienceは、システム上で実行してイベントデータレートを計算できるスクリプトを提供します。デフォルトでは、スクリプトは最大5つのSVMに対して実行されます。環境に5つを超えるSVMが含まれている場合は、それに応じてスクリプトを変更できます。SVMの数に関係なく、スクリプトが平均イベントレートの読み取り値を取得するのに約5分かかります。スクリプトを実行する前に、以下を用意する必要があります：

* link:suspicious-user-activity.html["ユーザーアクティビティエージェントを設定しました"]
* クラスタ IP アドレス
* クラスタ管理者のユーザ名とパスワード
* Linuxマシンにインストール済み `sshpass`（コマンド `sudo yum install -y sshpass`を使用してインストールできます）


.手順
. ユーザーアクティビティエージェントが稼働しているマシンから、管理者権限でスクリプトを実行します： `/opt/netapp/cloudsecure/agent/install/svm_event_rate_checker.sh`
. プロンプトが表示されたら、クラスタのIPアドレス、管理者ユーザー名、および管理者パスワードを入力してください。
. このスクリプトの実行には約5分かかります。処理が完了すると、コマンドラインにイベント発生率が表示されます。例えば、"Svm svm_rate is generating 100 events/sec."のように表示されます。
+
イベント発生率を使用して、サイジングを計算してください。

=== クラウドネットワークアクセスルール

関連する地域 (アジア太平洋、ヨーロッパ、または米国) のクラウド ネットワーク アクセス ルールを確認します。


IMPORTANT: 初期インストール時に、 `<site_name>`をワイルドカード(`*`）権限に置き換えます。エージェントがアクティブ化され、完全に動作可能になったら、権限をサイト名に置き換えることができます。サイト名については、NetAppの担当者にお問い合わせください。


NOTE: ユーザーアクティビティエージェントはNetApp Data Infrastructure Insightsテクノロジを使用しているため、 `cloudinsights`エンドポイントを使用します。詳細については、link:concept-user-behavior.html#user-activity-forensics["ランサムウェア耐性とData Infrastructure Insights"]を参照してください。
